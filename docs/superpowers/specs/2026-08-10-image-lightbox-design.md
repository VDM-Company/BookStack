# Image lightbox for the `refresh` theme

**Date:** 2026-08-10
**Status:** Approved, ready for implementation planning
**Target:** BookStack v26.05.3, `themes/refresh`

## Problem

Clicking an image in a BookStack page navigates away from the page to the raw
image file. BookStack inserts images wrapped in a link to the full-size original
— `[![alt](thumb)](full)`, see `resources/js/markdown/actions.ts:47` — so the
click target already exists, it just does the wrong thing. The reader loses their
place and has to press Back.

Core BookStack has no lightbox. Nothing in `resources/js` implements one.

## Goal

Clicking an image in page content or a comment opens it enlarged in an overlay
on the same page, with keyboard and pointer navigation between the images around
it, and closes back to the exact reading position.

## Constraint

**No core file is modified.** BookStack has no plugin system; its only extension
point is the theme system, and only one theme can be active (`APP_THEME=refresh`).
The feature therefore ships as a self-contained module inside the existing
`refresh` theme, following that theme's stated philosophy: tiny, additive, and
degrading to stock BookStack if it fails.

## Files

```
themes/refresh/
├── src/_lightbox.scss                    new    overlay styles
├── src/theme.scss                        edit   +1 `@use "lightbox";`
├── public/css/theme.css                  build  regenerated by ./build.sh, committed
├── public/js/lightbox.js                 new    the behaviour
├── layouts/parts/custom-head.blade.php   edit   +1 <script defer> with CSP nonce
└── README.md                             edit   document the module
```

Reverting the feature is: delete two files, revert three lines, rebuild.

`lightbox.js` is a second script rather than an addition to `theme.js` because
the two have unrelated jobs — `theme.js` adds DOM hooks for styling, this adds an
interaction — and keeping them separate keeps either one removable on its own.

## Behaviour

### Trigger

One delegated `click` listener on `document`. Nothing is scanned at load, so
comments loaded or edited after page load work with no re-initialisation.

The lightbox opens only when **all** of the following hold:

1. Primary button, no `ctrl` / `⌘` / `shift` / `alt` modifier, and the event is
   not already `defaultPrevented`.
2. `event.target.closest('img')` exists and sits inside `.page-content` or
   `.comment-box .content`.
3. That image is **not** inside `[contenteditable]` or `.editor-content-area`.
4. A source URL can be resolved (below).

Failing 1 or 4 falls through to the browser, so `⌘`-click and middle-click still
open the original in a new tab.

### Source resolution

Let `a = img.closest('a')`.

| Case | Result |
|---|---|
| `a` exists, href is an image | open lightbox at `a.href`, `preventDefault()` |
| `a` exists, href is anything else | **do nothing** — the link navigates as before |
| no `a` | open lightbox at `img.currentSrc` |

An href counts as an image when its resolved pathname ends in
`.png .jpg .jpeg .gif .webp .avif .svg .bmp .ico` or contains `/uploads/images/`.
Resolution uses `new URL(href, location.href)` so relative and absolute hrefs
behave identically, and a query string does not defeat the extension test.

This preserves images an author deliberately used as navigation — an image
linking to a book or an external site keeps navigating.

`preventDefault()` is called only after the overlay has been built successfully.
If any step throws before that, the plain link still works.

### Editor exclusion

The WYSIWYG editor's editable root is a **same-document** contenteditable `div`
that carries the `page-content` class — `resources/js/wysiwyg/index.ts:56` sets
`editorClass: 'page-content'` and `resources/js/wysiwyg/ui/index.ts:8` renders it
with `contenteditable: 'true'`. Without rule 3 above, clicking an image while
editing would open the lightbox instead of selecting the image, making images
uneditable. This is the single most important guard in the feature.

The markdown editor's preview is an `<iframe sandbox="allow-same-origin">`
pointed at `about:blank` (`resources/views/pages/parts/markdown-editor.blade.php:53`),
a separate document, so a listener on the parent `document` never sees its clicks.
No guard needed, but it must not regress.

Exports are unaffected: `layouts/export.blade.php` includes
`exports.parts.custom-head`, a different view from the `layouts.parts.custom-head`
the theme overrides, so the script never loads there.

### Overlay

Built once on first use, appended to `body`, and reused. Classes are prefixed
`rl-` to guarantee no collision with core.

```html
<div class="rl-backdrop" role="dialog" aria-modal="true" aria-label="Image viewer" hidden>
  <button class="rl-close" aria-label="Close">×</button>
  <button class="rl-prev"  aria-label="Previous image">‹</button>
  <button class="rl-next"  aria-label="Next image">›</button>
  <div class="rl-stage"><img class="rl-img" alt=""></div>
  <div class="rl-bar"><span class="rl-caption"></span><span class="rl-counter"></span></div>
</div>
```

### Opening

1. Record `document.activeElement` for later restore.
2. Paint the already-cached thumbnail (`img.currentSrc`) immediately, then load
   the full-size original in a detached `Image()` and swap on decode. A spinner
   appears only if that takes longer than 150 ms, so small images never flash one.
3. Lock body scroll, compensating for the scrollbar width so the page behind does
   not shift.
4. Unhide the backdrop and move focus to the close button.

If the full-size original fails to load, the thumbnail stays on screen. Nothing
appears broken.

### Gallery

The image set is the eligible images inside the **same** container as the one
clicked, in DOM order — the page body is one set, each comment is its own. This
keeps `←`/`→` predictable.

The counter reads `3 / 8`. With only one image in the set, the counter and both
arrow buttons are hidden entirely.

### Zoom toggle

Default state is fit-to-viewport with `cursor: zoom-in`. Clicking the image
switches to natural size inside a pannable stage, with drag-to-pan via pointer
events (one code path for mouse and touch) and `cursor: grab` / `grabbing`.
Clicking again returns to fit. A pointer movement beyond a few pixels counts as a
drag, not a click, so panning does not collapse the zoom.

If the image already fits entirely within the viewport, the toggle is inert and
the cursor stays default — no dead interaction.

Zoom matters because the lightbox shows the full-resolution original: a 3000px
screenshot is otherwise scaled down to fit and is no more readable than before.

### Closing

`Esc`, the `×` button, or a backdrop click where the click target is the backdrop
itself — not the image and not a button. Closing restores scroll and returns
focus to whatever had it before opening.

### Keyboard

| Key | Action |
|---|---|
| `Esc` | close |
| `←` / `→` | previous / next image in the set |
| `Tab` | cycles within the overlay's three buttons (focus trap) |

### Accessibility

`role="dialog"` with `aria-modal="true"`, a focus trap over the three controls,
focus restore on close, English `aria-label`s on every control, the image's own
alt text as the visible caption, and `prefers-reduced-motion` dropping the
fade/scale transition.

### Text

English string constants in the script. The only visible text is the counter and
the image's own alt text; everything else is an `aria-label`. No theme lang files,
no strings passed from Blade.

## Styling

`src/_lightbox.scss`, imported last in `theme.scss` so it lands at the end of the
cascade. Self-contained under the `rl-` prefix — it overrides no core selector, so
it is exempt from the `ld()` dark-mode mixin wrinkle documented in the theme
README. The overlay is dark in both colour schemes by design.

The one rule that touches existing markup is the hover affordance on eligible
images (`cursor: zoom-in`), scoped to the same selectors and exclusions as the
click handler so it never appears in the editor.

## Failure behaviour

The whole module is wrapped in the `try/catch` shape already used by `theme.js` —
the theme's stated rule is "never let the theme break the page".

If a future BookStack release renames `.page-content` or `.comment-box .content`,
the handler stops matching and images revert to plain links. It fails safe and
silently, the same way the theme's CSS does.

## Deliberately not included

Scroll-wheel and pinch zoom, swipe gestures, a download button, a slideshow, a
thumbnail strip, captions beyond alt text, images in book/chapter/shelf
descriptions (the only available hook there is a generic `.text-muted.break-text`
that would match unrelated text blocks), and any admin setting to configure any
of this.

## Verification

Manual, matching the theme's existing convention — no JS test harness is added,
because the theme's value is being a drop-in directory with no build or test
dependency.
